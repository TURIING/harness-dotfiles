# HAR: 文档
---

生成/增量更新项目知识文档，供 AI 快速、全面地了解项目。

**这是一个审阅式生成命令，不是扫描生成器。** 每次执行先通读全部 docs，起草候选更新，向用户呈现，经多轮纠正、用户明确确认后才落盘。文档是"项目当前状态"的快照，从代码现场派生，不写历史记录。只记录从代码可验证的事实，不臆测。

---

**输入**: `/har:doc [主题|模块|类]`

- 携带主题/模块/类名 → 针对该项生成或更新
- 无参 → 根据当前对话上下文推断要处理的主题，不确定就询问

**输出位置**: `.dsh/har/docs/`

## 固定骨架（不可扩展）

```bash
.dsh/har/docs/
├── INDEX.md          # 检索地图：分类规则 + 模块/类 → 文件 映射
├── overview.md       # 项目定位 + 总架构图
├── architecture.md   # 分层 / 数据流 / 生命周期
├── build.md          # 构建 / target / 依赖 / 输出布局
└── modules/          # 一模块一文件，文件名 = 模块名
```

## 类描述模板

写入模块文档正文。字段规则：
- **作用**（必写）
- **业务逻辑**（有才写；纯数据结构/句柄封装省略）
- **实现原理**（值得写才写；太简单的省略；一句话点到为止）
- 不写依赖关系

```markdown
## CircularBuffer
- 作用: 命令流写入的环形内存缓冲
- 实现原理: "软环形"——2×size 匿名映射，线性写入、滑动回收
```

## 执行流程

### 1. 通读全部 docs（硬约束）

干活前必须 Read 全部 `.dsh/har/docs/` 文档：

```bash
ls .dsh/har/docs/           # 不存在 → 先初始化骨架
ls .dsh/har/docs/modules/   # 列出全部模块文档
```

读取 INDEX + overview + architecture + build + modules/*。目的：
- 掌握骨架全貌 → 增量"插对位置"
- 发现跨文档矛盾、过期内容、重复

**文档必须保持精简**（"一屏读完"），否则通读成本失控。模块文档超长时拆模块文件，而非加长。

### 2. 定位目标文件

按分类规则确定本次要写哪个文件：

- 类 → 所在模块文档
- 模块 → `modules/<模块>.md`
- 概览/架构/构建 → 对应顶层文档
- 横切主题（线程模型、内存管理）→ overview 或 architecture
- 独立仓库（如 3rd/Utils）→ 不深入，只摘要

无参时：根据当前对话上下文推断主题，不确定就询问用户。

### 3. 检索现状

读目标文件现有内容 + 读相关代码，标出：
- **新增**：代码里有、文档没有
- **变化**：文档描述与代码现状不符
- **过期**：文档描述的对象已不存在/已改名

### 4. 起草（不写盘）

生成候选更新，严格遵循类描述模板。模块首次接触时，草案标注"我按 XX 切的模块边界，是否合理？"

### 5. 呈现

向用户展示草案，明确标注：
- 哪些是新增、哪些是修正、哪些判断为过期
- 模块边界的切分建议

**过时内容更新前必须询问用户。**

### 6. 纠正

根据用户反馈多轮迭代，直至用户满意。用户可纠正模块边界、类描述、分类归属。

### 7. 确认落盘

用户明确同意后：
- 写入正确位置
- **同步更新 INDEX.md**（模块/类映射 + 检索地图）
- 若为新模块，登记进 INDEX

## 模块切分

```bash
# 查看候选模块边界
ls src/ include/
```

- 优先按顶层目录 / 命名空间切，其次按功能边界
- 边界由用户在确认环节拍板，命令只给建议
- 目标是"一屏能读完"——类多就拆模块文件，不堆长文

## 初始化

首次执行 `.dsh/har/docs/` 不存在时，先建骨架：

```bash
mkdir -p .dsh/har/docs/modules
```

生成 INDEX.md（含分类规则）+ overview.md（项目定位 + 总架构图）起步，其余文件按需生成。

## 护栏

- **通读全部 docs 是硬约束**，任何执行前必须先读
- 不写盘直到用户确认
- 过时内容更新前询问用户
- 一模块一文件，不一类一文件
- 不写依赖关系，业务逻辑/实现原理"有才写"
- 独立仓库不深入
- 不提交代码
