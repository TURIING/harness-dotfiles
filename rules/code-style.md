# 代码编写原则
- 第三方库一律使用`git submodule`的方式获取，并存放在`3rd/`
- 代码注释规范
  - 默认不写任何注释，只有满足以下任一条件才允许写：
    - 非平凡逻辑：指针/位运算、算法关键步骤、状态机转移、内存布局或对齐
    - 隐含约束或前置条件：调用顺序、线程模型、生命周期要求
    - 反直觉写法：性能考量、平台差异、兼容性处理
  - 写注释前先走决策树，按顺序判断：
    - 这段代码删掉注释 5 秒内能看懂吗？能 → 不写
    - 看不懂是因为代码本身难懂？→ 先改名/拆函数，改不动才允许写注释
    - 允许写后，注释只解释"为什么/意图"，不解释"代码在做什么"
  - 禁止：
    - 逐行复述代码行为、显而易见操作的说明、与代码重复的注释
    - 注释与函数名/变量名表达同一信息（函数名即注释，如 `// 获取用户名称` 配 `GetUserName()`）
    - 文件头注释：项目名、作者、日期、`@file` 等一律不写
    - 注释掉的代码（删除而非注释）
    - 命名空间闭合注释，比如写注释提示某个花括号是属于哪个命名空间的
  - 数量约束：单个函数体内注释不超过 3 条，注释行数不超过代码行数的 10%
  - 格式：注释使用中文，写在代码行上方
  - 对照示例
    - ❌ 复述代码：`// 遍历所有用户，把名字打印出来` 配 `for (auto& user : users) Print(user.name);` → 删除
    - ❌ 与代码重复：`// 计算帧时间` 配 `float delta = now - last;` → 删除
    - ✅ 解释意图：`// 用上一帧时间，避免首帧 delta 巨大导致物理跳变` 配 `float delta = Clamp(now - last, 0.0f, kMaxFrameTime);` → 保留
  - 除了抽象类的接口函数，否则不需要写函数名、参数注释
  - 移植其他项目代码或外部代码片段时，不照搬原注释：去掉文件头注释、license 注释及不符合本规范的注释，一律按本规范重写
- 代码编写风格
  - 尽量封装可复用的代码，比如利用宏定义、template等
  - 定义（常量、宏、枚举、别名等）按适用范围决定存放位置，不散落、不越层
    - 常规/通用/可复用的定义：存放到项目统一定义通用代码的文件中，一处定义、各处复用
    - 仅适用于本功能的定义：存放在该功能范围内的定义文件中
    - 反例：通用定义散落在某功能模块内部，其他模块被迫 include 该功能模块的文件才能使用
    - 正例：通用定义集中在项目统一文件中，各功能按需引用；功能私有定义留在本模块内
    - 升级：定义最初存放在功能范围内，一旦被其他功能复用，应上移到项目统一层，禁止就地复制一份
